# Deploying

One Docker web service (Render's free plan works) and one hosted Postgres (Neon's free plan works). The server holds no
AI, search or contact keys: every operator saves their own on the **API keys & spend** page.

## 1. Database (Neon)

1. Create a Neon project. Copy the **pooled** connection string (host contains `-pooler`), as given:
   `postgres://user:pass@ep-...-pooler.region.aws.neon.tech/neondb?sslmode=require`.
   The app converts it for asyncpg and turns off prepared-statement caching, which Neon's pooler (PgBouncer) needs.
2. Create a **second branch** for tests and put its URL in your local `.env` as `TEST_DATABASE_URL`. Tests, evals and
   the demo refuse to open the database named in `.env`'s `DATABASE_URL`, so they can never touch production.
3. Nothing else: the schema is created by Alembic migrations when the app starts.

Checked on 2026-10-29 against a Neon test branch with `scripts/check_persistence.py`: the migrations built the schema
(version 0005), an account, a client and an encrypted key written by one process were read back by another, and the
app booted in production mode in between (`/healthz`: production, PostgreSQL, not ephemeral, no fixtures; no test
sign-in route) with the data intact.

## 2. Google sign-in

Google Cloud console → APIs & Services:

1. **OAuth consent screen:** type External, publishing status *In production*, scopes `openid`, `email`, `profile`
   only. Add the two public pages: terms `https://<your-host>/termsofservice`, privacy `https://<your-host>/login/policy`.
2. **Credentials → Create OAuth client ID → Web application.** Authorised redirect URIs:
   `https://<your-host>/auth/google/callback` and, for local work, `http://localhost:8000/auth/google/callback`.
3. Copy the client ID and secret into `GOOGLE_OAUTH_CLIENT_ID` and `GOOGLE_OAUTH_CLIENT_SECRET`.

## 3. The web service (Render)

Render dashboard → New → Blueprint → this repository (`render.yaml`). Then in the Environment tab:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the Neon pooled URL |
| `APP_BASE_URL` | `https://<your-service>.onrender.com`, the bare address with no path such as `/login` (the Google redirect is built from it) |
| `ENCRYPTION_KEY` | `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Keep it: if it changes, saved API keys can no longer be read (operators re-enter them). To rotate, set `ENCRYPTION_KEYS=new,old` |
| `JWT_SECRET` | generated by the blueprint |
| `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET` | from step 2 |
| `CONTACT_EMAIL` | the address shown on the privacy page for data requests |
| `ALLOWED_EMAILS` | optional, comma-separated: only these Google accounts may sign in |

Production refuses to start if `JWT_SECRET` is weak, `ENCRYPTION_KEY` is missing or invalid, or mock models are
requested. Render auto-deploys from `main`; a deploy that fails to start leaves the previous version serving.

First v2 deploy (2026-10-30): the first attempt stopped at startup with "ENCRYPTION_KEY must be set in production"
(the variable was not set yet) while v1 kept serving; once the variables were set it deployed and
`scripts/check_deploy.py` passed.

## 4. After every deploy

```bash
.venv/bin/python scripts/check_deploy.py https://<your-service>.onrender.com
```

It fails unless `/healthz` says production, Postgres, not ephemeral, no fixtures and live models; the sign-in, terms and
privacy pages answer; the test-only sign-in does not exist; and the Google redirect points back at this host.

## 5. Run it locally

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # fill in JWT_SECRET, ENCRYPTION_KEY, DATABASE_URL, Google sign-in
DATABASE_URL="sqlite+aiosqlite:///./local-check.db" .venv/bin/uvicorn app.main:app --port 8000
```

The `DATABASE_URL=` prefix keeps a local run off the production database when `.env` names it (a new version would
otherwise migrate production on start). Google needs `http://localhost:8000/auth/google/callback` as a redirect URI.

Labelled synthetic demo (mock models, fictional clients, a sign-in button without Google):

```bash
APP_ENV=demo DATABASE_URL=sqlite+aiosqlite:///./demo.db .venv/bin/uvicorn app.main:app --port 8010
```

## 6. Limits of this setup

- One worker: the orchestrator and the rate limiter are in-process. A run in progress during a restart resumes from
  its last finished step when the app starts again.
- Render's free plan sleeps after 15 idle minutes; the first request then takes about a minute. Data is not affected
  (it lives in Neon).
